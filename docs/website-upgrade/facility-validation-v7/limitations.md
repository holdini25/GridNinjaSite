# V7 limitations and deployment prerequisites

- The facility is a synthetic illustration. Activity, geometry, and inspection views do not calculate capacity or establish operating authority. Assessment quantities and conclusions remain authoritative; Storage remains **“Contribution and duration unassessed.”**
- Rear-row rack fronts are obstructed in their in-place detail views: sampled front-module points on Rack 07–11 are fully blocked by the front row, and Rack 12 is partly blocked. The selected rack remains the camera target. The inspector now identifies that obstruction and offers an explicit representative rack assembly on `/demo`, or a named demo link from home. The separate assembly explains construction; it is not a claim to reveal the selected installed rack. See the [occlusion audit](../../../build/facility/facility-v7/rack-detail-occlusion-audit.json).
- Static decisions and native evidence links remain available without JavaScript. Inquiry submission requires JavaScript and security verification. URL topic/source context is applied after hydration; the editable public topic is independent of visitor inquiry text and does not alter assessment identity.
- Apply the additive nullable-topic [database migration](../../../drizzle/0002_public_assessment_topic.sql) through the normal release process **before deploying the updated contact application**. It has not been applied during this implementation. No external inquiry was sent. Existing records, attempts, and deliveries without a topic remain valid; see the [intake notes](../facility-v7-contact-topic.md).
- The retained startup changes improve mobile home LCP, but final production measurements do **not** pass the 2.5-second gate: mobile medians are **2.606 seconds for home and 2.746 seconds for `/demo`**. The graphics/transfer measurements pass on the Mac; that does not waive the mobile page-load requirement. See [final performance](performance.md) and the [validation report](README.md).
- Simulator and emulated-browser evidence do not establish physical-phone GPU performance, memory pressure, energy use, or temperature. Physical-device sustained tests and native Safari/VoiceOver checks remain separate public-rollout requirements. Still captures do not establish animation cadence.
- The second M5 Pro Chrome sustained run passes 900 seconds with stable resource counts; the earlier run ended at approximately 485 seconds on unexpected page closure and remains preserved with cause unknown. `pmset` reported no recorded thermal/performance warning level or CPU power status before/after the passing run. That is not a temperature/energy measurement or thermal guarantee. GPU timestamp samples were not collected by the harness.

The local preview and rollback modes remain available while these release requirements are addressed. No public deployment is claimed.
